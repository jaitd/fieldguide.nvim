# What the recording does, one step per line: `send <keys>` types into the
# recorded Neovim, `wait <seconds>` lets what happened land, `#` is a comment.
#
# Keys are what `nvim --remote-send` takes, so <leader> is a literal space here
# and <CR> is the Enter key. The panel's prompt opens in insert mode, so a
# question is typed as itself: a leading `i` would end up inside the question.
#
# The waits are wall-clock waits on a model. They are generous on purpose, and
# `asciinema rec --idle-time-limit` caps the dead air in playback, so a wait
# that is too long costs a second of playback and a wait that is too short
# costs the take.

# The config the agent is confined to, open on the left.
wait 2

# The panel. Nothing is bound by default; the demo config opts in to <leader>fg,
# which is what most people will set.
send  fg
wait 3

# 1. Answered from the plugins this config has installed, not from a model's
#    memory of what plugins exist.
send which plugins do I have installed, and what is gitsigns for?<CR>
wait 45

# 2. A live keymap, traced to the plugin that set it and the line that did.
send what sets <lt>leader>gb, and which plugin does it come from?<CR>
wait 45

# 3. A plugin this config does not have. Nothing installed can answer it, so
#    the answer comes from the index of the ecosystem instead.
send I have no file explorer — what would you suggest, and why that one?<CR>
wait 45

# 4. Back to what is installed, and this time it makes the change: the edit
#    lands in the config, and a sandboxed boot of the edited config is
#    attached to it, so "it still starts" is checked rather than hoped.
send I want inline git blame on by default — can you set that up?<CR>
wait 70

# The file on the left, reloaded from disk, showing what was written.
send <C-\><C-n>
wait 1
send <C-w>h
wait 1
send :e!<CR>
wait 2
send /current_line_blame<CR>
wait 12
